# 限价开仓撮合与成交结算

当前撮合进程只消费 `stream:market-ticks` 中由优美利 WebSocket 产生的
`LIVE_CALLBACK` 行情。REST 快照、行情最新值 Hash 都不会触发撮合。

撮合使用 VN 独立流动性模式：每笔活动订单独立使用一档盘口数量，不模拟
真实交易所的订单排队，也不在不同订单之间共享或扣减盘口量。买入限价达到
卖一价时按卖一成交，卖出限价达到买一价时按买一成交。

## 行情积压语义

系统当前不做行情年龄、重复或乱序过滤。Matching Worker 停机期间已经进入
Stream 的 WebSocket Tick，代表订单存续期间真实出现过的市场机会。Worker
恢复后按 Consumer Group 的 Stream 顺序继续补撮合，成交时间使用原始
`tick.event_time`，并保存 `market_event_id` 和 Redis 消息编号，不使用恢复
处理时的当前时间替代成交时间。

## 资金转换

订单部分成交时，剩余冻结保证金和手续费按“本次成交量 / 成交前剩余量”
分配；最后一笔成交直接使用全部剩余冻结金额，消除 Decimal 六位小数舍入
尾差。成交不会再次减少 `available_cash`，因为下单接收阶段已经预留全部
资金。手续费从账户现金余额和权益各扣一次。

第一版不按实际成交价重新计算成交保证金或手续费。成交保证金直接采用订单
冻结保证金的分配值，确保改善价成交时也不会引入二次资金检查和账户透支。

## 可靠性

同一订单和同一 `market_event_id` 在数据库中具有唯一约束。Tick 在成交事务
提交后、XACK 前发生进程崩溃时，Pending 恢复会重新投递消息，已经成交的
订单通过该唯一键返回幂等成功，不重复扣款或增加持仓。

订单、账户、成交、持仓、逐笔持仓明细和两个 Outbox 事件在同一个 PostgreSQL
事务内提交。活动订单 Redis 索引由订单状态 Outbox 事件异步更新，数据库始终
是最终事实来源。
